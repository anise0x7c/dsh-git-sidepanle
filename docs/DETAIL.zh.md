# Git 源代码管理

为右侧栏提供 VS Code 风格的源代码管理界面。它读取当前会话工作目录所在的 Git 仓库，让你无需离开 Web 界面即可查看并操作更改。

面板使用宿主自身的主题令牌、字号层级与组件规范绘制，因此会跟随浅色/深色主题，并与侧栏的行高、标题、分隔线、控件与菜单保持一致。

## 打开方式

打开右侧栏（会话标题栏右端角的展开按钮），在起始页选择**源代码管理**。侧栏切换快捷键也可以直接打开该页面：桌面应用和 Windows、macOS 的 Web 界面使用 `Ctrl+Shift+G`（macOS 为 `Cmd+Shift+G`）；Linux 浏览器保留了该组合键，因此 Web 界面在那里没有默认快捷键，可在 DSH 的快捷键设置中自行指定。

Git 标签页及其差异标签页都位于右侧栏的常规停靠区域，可以分屏、浮动，并随侧栏布局一起恢复。

若会话工作目录不在 Git 仓库中，面板会注明该目录，并且只提供刷新操作。若 Host 无法运行 Git，面板会说明如何让 Git 可用并提供重试。

## 显示内容

- **分支标题栏**：当前分支、分离头指针或尚无提交状态、上游跟踪以及领先/落后数量。点击标题栏可切换其他本地或远程跟踪分支。远程操作位于提交图的分组标题中。
- **提交框**：多行提交信息，`Ctrl+Enter`（macOS 为 `Cmd+Enter`）提交。输入框默认一行高，随文字换行增高，最多十行，之后提交信息在框内滚动，不会再把更改列表挤下去。提交按钮占满整行并带对勾图标，右端的展开按钮打开菜单：**提交**、**提交(Amend)**、分隔线、**提交和推送**、**提交和同步**；按下 `Escape`、点击菜单外或操作开始时菜单关闭。两半属于同一个控件：消息为空或操作进行中时二者一起禁用并一起变暗，此时菜单也无法打开。所有操作都只提交已暂存的更改；没有任何暂存时，提交、提交和推送、提交和同步会先询问是否暂存全部更改，提交(Amend) 不会自行暂存。提交(Amend) 用输入的信息和已暂存的更改替换 HEAD，当前分支还没有提交时会被拒绝。提交和推送先提交再推送；提交和同步先提交，合并拉取上游，拉取成功后才推送；没有上游时二者不可用，远程步骤失败时会保留刚创建的提交。提交失败会保留提交信息与暂存状态，主按钮的提示仍会说明提交的影响范围。
- **合并更改 / 已暂存的更改 / 更改**：与 VS Code 相同的三个更改分组，均为按路径排序的单层列表，不再显示文件夹行。每行依次显示该文件自己的类型图标（与 Web 应用文件侧栏的字形与配色一致，宿主未提供时回退为通用文件图标）、文件名、变暗的父目录，以及行尾按状态着色的状态字母（`M` 修改、`A` 添加、`D` 删除、`R` 重命名、`U` 未跟踪、`!` 冲突），与展开提交列出的文件一致；完整路径保留在行的提示中。悬停行可执行暂存、取消暂存或放弃更改。工作区干净时，更改区域只用文字说明，不再显示图标。
- **可调分栏**：更改分组在提交图上方的独立窗格中滚动，因此较长的更改列表不会把提交历史挤到下面。拖动两者之间的分割线即可改变比例；聚焦分割线后，`ArrowUp`/`ArrowDown` 每次移动 5%，`PageUp`/`PageDown` 移动 10%，`Home`/`End` 跳到极限。两个窗格都保留可用的最小高度，并各自保持滚动位置。打开提交详情再返回时会保留该比例，关闭并重新打开标签页后恢复默认。
- **标题吸顶**：当某个更改分组或提交图高于所在窗格时，滚动过程中它的分组标题会停留在窗格顶部，并以面板背景遮住从下方滚过的行，标题上方也不会露出内容。标题在窗格滚动前就已位于该位置，因此开始滚动时只有行在移动，标题本身不会先挪动。前一分组滚出后，下一个分组的标题接替该位置，因此同一时刻只固定一个标题。
- **提交图**：复刻 VS Code 的“源代码管理图形”，展示跨本地分支、标签和远程跟踪分支的近期提交，并按 VS Code “全部”筛选的拓扑顺序排列。连线遵循 VS Code 的泳道规则：提交位于指向它的最左侧连线上，第一父提交沿该位置延续；指向同一提交的其他连线在该行弯入节点；合并提交的每个额外父提交都在最右端新开一条连线；结束的连线右侧的连线在同一行左移补位。每行高 22 像素、泳道间距 11 像素，细线绘制，汇入与分出使用四分之一圆弧，左移使用短 S 形弯；两行相接处的连线在任何缩放下都保持连续。节点采用 VS Code 的形状——普通提交为实心圆点，合并提交为带中心点的圆环，当前检出的提交为空心圆环——节点与连线之间留有小间隙，鼠标悬停在该行时间隙闭合。颜色与 VS Code 一致：新连线依次轮换琥珀、洋红、棕、青绿、紫五色；当前分支为蓝色，其上游为紫色，其基准分支在与上游不同时为橙色（优先使用已配置的 VS Code 合并基准，否则使用默认远程的默认分支）。每行显示提交主题（当前检出的提交加粗）和淡色作者，随后是 VS Code 风格的彩色引用徽标：第一个引用显示名称，其余引用按颜色分组，以本地分支、远程分支和标签图标呈现，代表多个引用时显示数量。提交主题、作者、短 ID、相对时间与全部引用都在行提示中；激活提交行会在其下方展开更改的文件。初始最多显示 60 个提交；滚动到提交图窗格的末尾会继续在已加载的行下方追加更早的 60 个提交（列表末尾的“加载更早的提交”按钮提供同一页），已显示的行保持原位，原先延伸到图底部的连线会连接到各自的提交。加载到最后一页后不再提供更多加载；某一页加载失败时会保留已加载的行并提供重试；刷新会从最新一页重新开始。其分组标题中带有获取、拉取、推送和溢出菜单。
- **展开提交**：点击提交图中的一次提交（或聚焦提交行后按 `Enter` / `Space`），会像 VS Code 的“源代码管理图形”一样在该行正下方列出这次提交更改的文件。每个文件占一行 22 像素，依次显示宿主应用针对该路径给出的文件类型图标（与文件侧栏的字形与配色一致，宿主未提供该图标集时回退为通用文件图标）、文件名、淡色目录，行尾是带颜色的状态字母，按路径排序；重命名文件的提示会给出原路径。提交图会贯穿展开的行：离开该提交的每条连线都竖直延续下去，提交自身所在的连线从该节点向下加粗为 3 像素，一直延伸到列出的行，下方提交的形状与颜色保持不变。可以同时展开多个提交，再次激活已展开的行即可收起。点击文件（或按 `Enter`）打开该提交范围内的差异。加载中、提交没有文件更改、读取失败（行内提供重试）或列表被截断时，会以一行提示说明。展开操作不会改动仓库、更改列表或提交框。
- **提交详情**：在提交行右键菜单顶部选择**查看详情**，会以一张带边框的毛玻璃卡片覆盖在面板上方，材质与底部操作浮层一致（主题半透明加背景模糊，不支持背景过滤时使用实色回退），更改列表、提交图与提交框都保留在卡片下方原位；卡片打开期间，下方内容不接受指针或键盘输入，并对辅助技术隐藏；卡片显示该提交的短 ID、主题、作者、相对时间、提交正文，以及按文件夹树呈现的更改文件：每个文件夹在所含内容的上方单独占一行，每深入一层多缩进一级；若某个文件夹往下只有一条不分叉的文件夹链，则用 `/` 连接各级名称合并为一行（例如 `aa/bb/cc`），整条链只占一级缩进而不是每个文件夹各占一级，链中出现文件或出现多个子项时即在该处停止合并。同一文件夹内先列子文件夹再列文件，均按名称排序，不区分大小写，数字串按数值比较。每个文件夹行用一个展开箭头代替文件夹图标：折叠时箭头朝右，展开时朝下，并且每次打开提交详情时都从全部展开开始；点击该行或按 Enter、空格即可收起或展开其整棵子树，文件夹行不打开差异，也没有菜单。文件行仍各带类型图标、重命名来源，行尾是按状态着色的状态字母。点击更改文件可打开该提交范围内的差异。卡片会从窗格右边缘滑入，返回时再向右滑出并露出下方内容。返回按钮会回到更改列表与提交图，保留之前的分栏比例、滚动位置与已展开的提交，且不触碰仓库；卡片打开时按 `Escape` 与返回按钮等效，除非操作浮层或分支菜单打开并占用该按键。相对第一父提交没有文件更改的提交会明确说明；读取失败会报告并提供重试；最多列出 1,000 个更改文件。
- **差异标签页**：点击任意更改文件。已暂存条目比较索引与已提交版本，未暂存条目比较工作区与索引，未跟踪文件按新增行显示。从展开的提交或提交详情打开的文件比较该提交与其第一父提交（根提交则与空树比较），标题栏会标明提交；纯重命名会给出说明，而不是显示空差异。二进制与超大文件会被标注而不是强行解码。

## 远程操作

分支标题栏保留分支标签与刷新控件。提交图的分组标题将获取、拉取和推送显示为更大的图标控件（仿照 VS Code 的“源代码管理图形”），悬停时只高亮指针所在的控件，而不是整行标题。获取按钮注明从所有远程库中抓取，并使用虚线双箭尾与拉取区分。其后的溢出省略号菜单提供拉取（变基）、同步、当前分支没有上游时的发布分支，以及包含添加远程仓库和移除远程仓库的“远程”分组。获取会更新所有已配置远程仓库的跟踪分支，并清理远程引用已被删除的跟踪分支；处于分离头指针或尚无提交状态时同样可用。拉取会合并上游；拉取（变基）会把本地提交变基到上游。推送会把当前分支发送到它的上游。当前分支没有上游时，拉取与推送不可用。同步先合并拉取，再推送；拉取失败时不会继续推送。其他 Git 操作进行期间，这些操作不可用。

发布没有上游的分支时，面板会把该分支推送到选定的远程仓库，并将对应的远程分支设为它的上游。只配置一个远程仓库时直接发布；配置多个时打开一个优先选中 `origin` 的表单；没有配置任何远程仓库时会说明需要先添加。分支选择器还会在单独的分组中列出 `origin/main` 这类远程跟踪分支，但不列出远程仓库的符号 `HEAD`。选择远程分支会签出同名的本地分支：本地不存在时创建该分支并以所选远程分支为上游，本地已存在时直接签出已有本地分支且不改变它的上游。

添加远程仓库会询问名称与 URL 并写入仓库配置；移除远程仓库会列出已配置的远程仓库，确认后只移除所选的那一个。远程仓库名称与 URL 都会校验，失败或取消的表单不会改动仓库；移除远程仓库时也会移除它的远程跟踪分支。远程仓库列表按需加载，显示加载与失败状态，并在变更后刷新。

远程操作在 Host 上执行，不经过 shell，会禁用 Git 自身的终端凭据提示并受超时限制；需要 Host 无法获得的凭据时，操作会以 Git 的消息或超时结束。请使用凭据助手或 SSH agent 完成认证；插件不保存凭据。添加远程仓库会写入仓库配置，并授权后续对该 URL 的网络操作，因此 Git 配置的传输方式、凭据助手与 hooks 仍属于本地信任边界。

打开面板时、每次操作后以及手动刷新时，状态都会刷新。标签页可见期间，宿主还会监视仓库，因此在终端中进行的编辑、暂存、提交、获取或切换分支会在约两秒内自动出现：工作区或索引的更改只刷新摘要与更改列表，`HEAD` 或引用的更改还会在已加载的行上移动提交图的当前分支、上游与基准分支颜色及徽标，而不会让提交图回到第一页。仅当当前检出的提交不在已加载的行中时，才重新加载最新一页。若宿主无法监视文件，面板会退回每隔数秒检查一次状态，并且不会向用户显示监视失败。

## 操作反馈

所有操作提示都使用 DSH 原生的 Toast 轻提示：成功操作沿用宿主自带的成功对勾图标，失败则使用警告图标，不再向面板插入提示条。普通提交、提交(Amend)、暂存全部后提交、提交和推送或提交和同步中的远程步骤、忽略、分离签出、创建／删除分支、创建标记、远程同步、发布、远程仓库配置和远程分支签出成功时使用成功样式；菜单目标已失效或面板正在忙碌的提示不使用成功样式。Toast 的位置、替换和关闭行为由宿主管理，不会改变更改列表或提交图的尺寸。提示跟随所选语言；忽略已跟踪文件时，仍会说明该文件继续被跟踪。

Git 失败以带警告图标的非成功 Toast 显示；可重试的读取失败会附带本地化的重试操作，失败不会显示成功 Toast。打开的操作表单在失败时保持打开并保留已输入的值；提交图、提交详情和差异面板在提示消失后仍保留紧凑的重试状态。原生 Toast 与共享服务都不可用时，行内 Git 控件、提交信息清空和刷新仍正常工作，不会回退到插件自己的提示条。

## 操作浮层

放弃更改确认、提交前暂存全部更改的询问，以及分支／标记表单，都会悬浮在 Git 面板底部上方，打开时从面板底边升起、关闭时再向下退出；升降过程中窗格内容与滚动位置保持不变，不会挤压更改列表或提交图，也不会移动分割线。浮层会随窗格宽度铺开，覆盖下方内容，左、右与底部均留出 4px 间距。它们统一使用跟随原生主题的圆角半透明毛玻璃卡片；浏览器不支持背景模糊时，使用实色背景保证可读性。

说明和表单位于独立的底部操作区上方。窄窗格中的长文件名、分支名与按钮文字会自动换行；较高的表单在内部滚动，操作按钮仍可触达。引用操作失败时，错误显示在打开的表单内，并保留已输入内容。面板中未被浮层覆盖的区域仍可操作；请求另一个确认或表单时，会替换尚未提交的浮层，而不会堆叠卡片或执行被替换的操作。

普通确认默认聚焦**取消**，空闲时按 `Escape` 可关闭且不执行 Git。正在退出的浮层不再接受操作。系统要求减少动态效果时，浮层与详情视图都直接出现或消失，不做位移动画。创建引用时默认聚焦名称输入框。操作进行中不能取消或重复提交。

## 右键菜单

右键点击任意一行，或聚焦更改文件、提交（以及分组标题或差异标题栏内的按钮）后按菜单键或 `Shift+F10`，即可打开右键菜单。菜单使用应用共享的右键菜单呈现，因此位置、关闭方式、焦点归还、主题与语言都与 DSH 其他部分一致。

- **更改文件**：查看更改、暂存或取消暂存、在可放弃时放弃更改、**添加到 .gitignore**，以及复制相对路径或完整路径。忽略操作会向仓库根目录的 `.gitignore` 追加一条以根目录为起点的字面路径规则，保留原有内容与换行风格，不重复添加同一条规则。未跟踪文件仍保留在磁盘上，但会在刷新后的更改列表中消失；已跟踪文件仍会被跟踪，成功 Toast 会明确说明这一点。若 `.gitignore` 是符号链接或其他非普通文件，会拒绝写入且不改动其目标。写入失败会报告错误，不会误报忽略成功。
- **分组标题**：该分组可执行的操作，包括暂存或取消暂存整组文件、放弃整组更改以及刷新。
- **提交**：首项为**查看详情**（只读取，因此其他操作进行中也可使用），随后是分隔线，再按 VS Code 的顺序分组：当提交带有本地分支头时，先显示**签出**子菜单（当前分支不可选），随后是**签出(已分离)**、分隔线、**创建分支**、非当前本地分支的**删除分支**子菜单、分隔线、**创建标记 (Tag)**、另一条分隔线、**复制提交哈希**与**复制提交消息**。远程跟踪分支、标签与 HEAD 标记不会混进分支子菜单。复制命令的原有内容不变：完整提交标识与主题行，不会额外复制提交正文。
- **差异标题栏**：复制文件的相对路径或完整路径。
- **展开的提交或提交详情中的文件**：复制相对路径或完整路径。过去的提交属于历史，因此这里不提供暂存、取消暂存与放弃操作。

创建分支时会先询问名称，在指定提交上创建并签出新分支。创建标记时会询问名称与可选消息：不填消息创建轻量标记，填写消息创建附注标记。空名称与取消不会执行 Git 命令；创建失败会保留已输入内容以便修改。删除分支需要先确认，Git 会拒绝删除当前分支或未合并分支。名称输入框会获得初始焦点；删除确认默认聚焦“取消”，空闲时按 Escape 可关闭。关闭后，只要原提交行仍存在，焦点就会归还该行。标记消息中普通 Enter 用于换行，点击按钮或按 Ctrl/Cmd+Enter 才提交。操作进行中会显示进度，失败后保留文本与逻辑焦点。引用操作成功后，分支标题、更改列表与提交图都会刷新。

完整路径以仓库根目录为基准；当会话运行在仓库的子目录中时，仓库根目录可能与会话工作目录不同。提交主题指提交信息的第一行，不包含正文。

菜单命令与等价的悬停按钮行为一致：相同的确认、失败提示与刷新。Git 操作进行期间，会修改仓库的菜单命令会变为不可用；若所选更改已被移除，则会明确提示而不会静默无操作。打开菜单本身不会执行任何 Git 命令。复制成功会有提示，剪贴板不可用时会明确报告而不会静默忽略。若宿主应用未提供右键菜单能力，面板及其所有行内控件仍照常工作。

## Host 执行与信任

所有 Git 命令都在 Host 上、于会话工作目录中通过单一本地路由（`/api/dsh-git-graph/rpc`）执行。该路由只接受未经代理的本机回环请求，要求本插件自有的请求头与同源浏览器标记；它从不经过 shell，也从不接受来自浏览器的仓库路径。

文件路径按字面名称处理，而不是 Git 通配或 pathspec 表达式，因此选择名称中含有模式字符的文件不会同时选中其他匹配文件。未跟踪预览与删除会核实当前 Git 分类，而不只信任旧文件行中的标记。直接文件访问拒绝符号链接父目录；未跟踪预览还会拒绝符号链接或非普通文件。放弃一个未跟踪符号链接本身时，只删除该链接，不会删除它的目标。

远程操作使用同一条路由和同样的参数数组执行方式。浏览器只发送操作、远程仓库名称、分支名称或远程仓库 URL；Host 从会话解析仓库，并在 Git 看到这些字段之前完成校验。获取、拉取、推送、同步与发布会禁用 Git 自身的终端提示，并受时间上限约束；需要 Host 无法提供的输入时，操作会以 Git 的消息或超时结束。添加远程仓库会写入仓库配置，并授权后续对该 URL 的网络操作。

仓库与本地账户仍须可信：正常的 Git hooks 和配置的辅助程序仍可运行。这些路径检查不是防御本地进程并发替换祖先目录的操作系统沙箱。

## 限制

- 认证必须是非交互式的：请配置凭据助手或 SSH agent。插件不保存凭据；需要 Host 无法提供的输入时，操作会以错误或超时结束，并且无法从面板取消正在进行的远程操作。
- 不支持强制推送、在上游已存在时推送到任意远程仓库、推送远程标记、删除远程分支、重命名远程仓库，或在创建后编辑远程仓库的 fetch 与 push URL。
- 不含 stash、任意合并或变基或初始化仓库。amend 仅限通过提交操作菜单替换最新提交。拉取可以合并或变基；标记创建仅在本地进行，支持轻量与附注标记，不包含远程标记操作。
- 冲突文件可以暂存以标记为解决，但没有合并编辑器。
- 一次只处理一个仓库：即包含会话工作目录的那个仓库。
- 提交的文件列表与单文件差异都以第一父提交为基准；不支持与第二父提交、任意其他提交或工作区比较。
- 本面板仅提供界面，不提供 Agent 工具，模型无法自行暂存或提交。
