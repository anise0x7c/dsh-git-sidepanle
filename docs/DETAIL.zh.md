# Git 源代码管理

为右侧栏提供 VS Code 风格的源代码管理界面。它读取当前会话工作目录所在的 Git 仓库，让你无需离开 Web 界面即可查看并操作更改。

面板使用宿主自身的主题令牌、字号层级与组件规范绘制，因此会跟随浅色/深色主题，并与侧栏的行高、标题、分隔线、控件与菜单保持一致。

## 打开方式

打开右侧栏（会话标题栏右端角的展开按钮），在起始页选择**源代码管理**。侧栏切换快捷键也可以直接打开该页面：Windows 与 Linux 为 `Ctrl+Shift+G`，macOS 为 `Cmd+Shift+G`。

Git 标签页及其差异标签页都位于右侧栏的常规停靠区域，可以分屏、浮动，并随侧栏布局一起恢复。

## 显示内容

- **分支标题栏**：当前分支、分离头指针或尚无提交状态、上游跟踪以及领先/落后数量。点击标题栏可切换其他本地分支。
- **提交框**：多行提交信息，`Ctrl+Enter`（macOS 为 `Cmd+Enter`）提交。只提交已暂存的更改；若没有任何暂存，提交时会先询问是否暂存全部更改。提交失败会保留提交信息与暂存状态。
- **合并更改 / 已暂存的更改 / 更改**：与 VS Code 相同的三个更改分组，均为按路径排序的单层列表，不再显示文件夹行。每行带有状态字母（`M` 修改、`A` 添加、`D` 删除、`R` 重命名、`U` 未跟踪、`!` 冲突）、文件名及其变暗的父目录；完整路径保留在行的提示中。悬停行可执行暂存、取消暂存或放弃更改。工作区干净时，更改区域只用文字说明，不再显示图标。
- **可调分栏**：更改分组在提交图上方的独立窗格中滚动，因此较长的更改列表不会把提交历史挤到下面。拖动两者之间的分割线即可改变比例；聚焦分割线后，`ArrowUp`/`ArrowDown` 每次移动 5%，`PageUp`/`PageDown` 移动 10%，`Home`/`End` 跳到极限。两个窗格都保留可用的最小高度，并各自保持滚动位置。打开提交详情再返回时会保留该比例，关闭并重新打开标签页后恢复默认。
- **提交图**：复刻 VS Code 的“源代码管理图形”，展示跨本地分支、标签和远程跟踪分支的近期提交，并按 VS Code “全部”筛选的拓扑顺序排列。连线遵循 VS Code 的泳道规则：提交位于指向它的最左侧连线上，第一父提交沿该位置延续；指向同一提交的其他连线在该行弯入节点；合并提交的每个额外父提交都在最右端新开一条连线；结束的连线右侧的连线在同一行左移补位。每行高 22 像素、泳道间距 11 像素，细线绘制，汇入与分出使用四分之一圆弧，左移使用短 S 形弯。节点采用 VS Code 的形状——普通提交为实心圆点，合并提交为带中心点的圆环，当前检出的提交为空心圆环——节点与连线之间留有小间隙，鼠标悬停在该行时间隙闭合。颜色与 VS Code 一致：新连线依次轮换琥珀、洋红、棕、青绿、紫五色；当前分支为蓝色，其上游为紫色，其基准分支为橙色（优先使用已配置的 VS Code 合并基准，否则使用默认远程的默认分支）。每行显示提交主题（当前检出的提交加粗）和淡色作者，随后是 VS Code 风格的彩色引用徽标：第一个引用显示名称，其余引用按颜色分组，以本地分支、远程分支和标签图标呈现，代表多个引用时显示数量。短 ID、相对时间与全部引用都在行提示中；激活提交行会打开提交详情。初始最多显示 60 个提交；滚动到提交图窗格的末尾会继续在已加载的行下方追加更早的 60 个提交（列表末尾的“加载更早的提交”按钮提供同一页），已显示的行保持原位，原先延伸到图底部的连线会连接到各自的提交。加载到最后一页后不再提供更多加载；某一页加载失败时会保留已加载的行并提供重试；刷新会从最新一页重新开始。
- **提交详情**：点击提交图中的一次提交（或聚焦提交行后按 `Enter` / `Space`），分栏会替换为该提交的详情：短 ID、主题、作者、相对时间、提交正文，以及该提交更改文件按路径排序的单层列表（带状态字母与重命名来源）。点击更改文件可打开该提交范围内的差异。返回按钮可在不触碰仓库的情况下回到更改列表与提交图，并保留之前的分栏比例。相对第一父提交没有文件更改的提交会明确说明；读取失败会报告并提供重试；最多列出 1,000 个更改文件。
- **差异标签页**：点击任意更改文件。已暂存条目比较索引与已提交版本，未暂存条目比较工作区与索引，未跟踪文件按新增行显示。从提交详情打开的文件比较该提交与其第一父提交（根提交则与空树比较），标题栏会标明提交；纯重命名会给出说明，而不是显示空差异。二进制与超大文件会被标注而不是强行解码。

页面打开时、每次操作后、手动刷新时，以及标签页可见期间每隔数秒，状态都会刷新。

## 右键菜单

右键点击任意一行，或聚焦更改文件、提交（以及分组标题或差异标题栏内的按钮）后按菜单键或 `Shift+F10`，即可打开右键菜单。菜单使用应用共享的右键菜单呈现，因此位置、关闭方式、焦点归还、主题与语言都与 DSH 其他部分一致。

- **更改文件**：查看更改、暂存或取消暂存、在可放弃时放弃更改，以及复制相对路径或完整路径。
- **分组标题**：该分组可执行的操作，包括暂存或取消暂存整组文件、放弃整组更改以及刷新。
- **提交**：复制完整提交 ID 或提交主题。
- **差异标题栏**：复制文件的相对路径或完整路径。
- **提交详情中的文件**：复制相对路径或完整路径。过去的提交属于历史，因此这里不提供暂存、取消暂存与放弃操作。

完整路径以仓库根目录为基准；当会话运行在仓库的子目录中时，仓库根目录可能与会话工作目录不同。提交主题指提交信息的第一行，不包含正文。

菜单命令与等价的悬停按钮行为一致：相同的确认、失败提示与刷新。Git 操作进行期间，会修改仓库的菜单命令会变为不可用；若所选更改已被移除，则会明确提示而不会静默无操作。打开菜单本身不会执行任何 Git 命令。复制成功会有提示，剪贴板不可用时会明确报告而不会静默忽略。若宿主应用未提供右键菜单能力，面板及其所有行内控件仍照常工作。

## Host 执行与信任

所有 Git 命令都在 Host 上、于会话工作目录中通过单一本地路由（`/api/dsh-git-graph/rpc`）执行。该路由只接受未经代理的本机回环请求，要求本插件自有的请求头与同源浏览器标记；它从不经过 shell，也从不接受来自浏览器的仓库路径。

## 限制

- 不含网络操作：fetch、pull、push 与远程管理不在本插件范围内。
- 不含 stash、创建标签、合并、变基、amend 或初始化仓库。
- 冲突文件可以暂存以标记为解决，但没有合并编辑器。
- 一次只处理一个仓库：即包含会话工作目录的那个仓库。
- 提交的文件列表与单文件差异都以第一父提交为基准；不支持与第二父提交、任意其他提交或工作区比较。
- 本面板仅提供界面，不提供 Agent 工具，模型无法自行暂存或提交。
