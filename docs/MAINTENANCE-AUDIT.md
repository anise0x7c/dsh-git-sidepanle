## 发现与处置

风险按本插件的本机、同源、可信仓库模型评估。自定义请求头、回环和 Origin 检查不能替代文件操作作用域校验，但这些发现也不意味着任意远程站点可以调用插件。

| 发现 | 影响与证据 | 本轮处置 |
|---|---|---|
| Git pathspec 与文件名混淆 | `--` 只结束选项，不关闭 `*`、`?`、`[]` 或 `:(...)` 等路径表达式；逐文件动作可能扩大到其他文件 | 用集中 Git 执行策略固定字面路径；真实仓库回归覆盖暂存、取消暂存、还原和两类 diff |
| 直接文件系统操作只做词法包含检查 | 未跟踪预览的 `stat/open` 会跟随最终链接；预览/删除的父目录链接可指向仓外 | 将路径校验与直接文件访问归属到专门模块；拒绝链接父目录；预览检查同一 no-follow 文件句柄并限制读取；允许删除链接本身但不触碰其目标 |
| 信任浏览器的 untracked 标志 | 被错误标记或捕获后已经暂存的文件会走 `unlink`，绕过跟踪文件还原流程 | 直接预览/删除前核实当前 Git 分类，拒绝把已跟踪文件当作未跟踪目标 |
| 包含关系判定过宽/过窄 | `startsWith('..')` 误拒 `..notes`；Windows 的跨盘 `relative` 可返回绝对路径 | 使用路径段边界与绝对结果检查；Windows 路径语义在跨平台纯测试中验证，不宣称 Windows 实机验收 |
| 写操作后的刷新被吞掉 | `inFlight` 直接返回，旧 status 快照可以成为写操作后的最终显示结果 | 串行读取并合并后续请求，让动作等待其所需刷新完成；覆盖错误和卸载 |
| watcher 可在卸载/取消后复活 | 目录发现的 await 之后没有存活性检查，旧请求也可能覆盖新的同面板订阅 | registry 终止围栏与每个面板的异步请求身份；以可控 Promise 验证而非依赖时序猜测 |
| 剪贴板回退清理不完整 | `execCommand` 或选择操作抛错会绕过临时 textarea 删除 | 使用 finally 清理，增加成功、拒绝与异常路径测试 |
| 重复与无消费者字段 | 菜单命令 schema 双份、路径复制动作重复，行字母规则在展示和 diff 寻址各算一次 | 收敛单一命令类型，删除已核实死字段，共享路径复制与分组/行字母规则 |
| 手工维护的架构约定 | 新模块可以跨 Host/client、引入运行时环或成为孤立文件而不触发原门禁 | 在现有测试命令内增加 TypeScript AST 依赖检查及故意违规夹具；不新增依赖 |
| UI 测试末行清理 | 断言失败会跳过全局 fetch/timer 和插件副作用清理，造成后续用例级联失败 | 在测试生命周期中登记兜底清理，并保持显式释放幂等 |

具体行为变化通过 LiteSpec 的 `harden-repository-paths`、`preserve-refresh-lifetimes`、`guard-module-boundaries` 三个独立 intent 管理。模块移动与不变契约见[架构](<ARCHITECTURE.md>)和[重构记录 §14](<REFACTOR-PLAN.md#14-安全与维护性重构2026-11-18>)。

## 重构取舍

- 不以行数为质量结论，不把大组件整体改名搬进另一个 controller。
- Git 面板继续装配现有 hooks；提取可直接测试的分组/字母规则。提交图的区段状态/分页、SVG 图层和行/徽标分别维护。
- 保留内聚的纯提交图算法及 VS Code oracle 等价测试。本轮不重写拓扑、颜色、曲线或 CSS。
- 不为三个提示协调函数额外建立一个仍然共享原状态的空壳 hook；没有减少状态源的拆分不做。
- Host 按执行、路径、文件操作、输入校验及领域写入划分，而不是为每个 RPC 建一个文件。
- 原有公开路由、bundle/React loader、菜单 captured-value、双语和主题契约不变；新增的状态拒绝也有英/中文映射，产物只从源码重新生成。

## 保留的边界与后续债务

1. **仓库和本地用户仍是可信的。** Git commit/switch 可运行用户配置的 hooks、过滤器或签名程序；现有规格明确支持 hook 拒绝提交，因此本轮不能悄悄禁用 hooks。继承的 Git 环境变量也可能影响仓库选择；应单独设计环境隔离和兼容策略，不把该插件描述为执行不可信仓库的沙箱。
2. **目录重命名竞态不是本次防护承诺。** Node 的可移植文件 API 没有完整的逐级 `openat` 能力；no-follow 句柄能保护最终链接，但不能承诺对抗同用户进程持续替换祖先目录、硬链接或挂载点。静态链接越界与浏览器误分类有回归，OS 级攻击不在验收范围。
3. **多浏览器页面的 panel id 尚未全局唯一。** 当前标识来自每页计数，两个页面可能互相覆盖同名 watch 订阅；主要影响实时更新/回退，并非仓外读写。后续应引入稳定的页面 nonce 和多页面隔离测试，避免更改现有菜单寻址时造成回归。
4. **unstage 的降级范围仍偏宽。** 任意 `restore --staged` 失败都会尝试 `rm --cached`，而注释只意图处理 unborn HEAD。应单列变更，用失败注入明确区分尚无提交与真正 Git/权限失败；本轮不夹带改变既有索引恢复语义。
5. **其余异步 hook 不是已全部验证。** 分支列表缓存失效、Session 绑定变化、reference-only 请求与历史分页间的顺序仍值得定向测试，不能把本次 status/watcher 修复宣传成统一异步框架。
6. **没有“清空所有死代码”的结论。** 编译器检查未使用声明，依赖门禁检查孤立的可执行源码；测试专用导出或语义上的无效分支仍需人工判断，不能通过删除测试来降低计数。
