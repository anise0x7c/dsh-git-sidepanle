# Design

- The live Client Inspect catalog does not expose `contextMenus`; the installed `@deepseek-ai/dsh-client-ui-context-menu` source confirms `notify(text, success?)` and its shared Toast rendering. Success is opt-in; stale/busy messages remain non-success.
- Keep context menus optional. Register the Git pane once and provide a stable notification callback through the Slot's `inject` face, as shipped DSH plugins do. The callback forwards to the currently bound optional service and becomes a no-op when that binding is disposed. Notification delivery errors are isolated from Git operations and refreshes.
- Add only the structural Slot injection member consumed by this bundle. Do not import any DSH Client package or UI primitive.
- Remove the private notice state, setter, four-second timer, inline markup and styling. Hooks emit notifications directly after completed operations or rejected stale/busy menu commands; repeated identical events still reach the host individually. Existing reference-operation notices already flow through the common action wrapper and migrate with it without adding notices to ordinary checkout or staging.
- Keep persistent errors, confirmation forms, all existing localized message keys, clipboard notifications and Git behavior unchanged. The host owns Toast placement, timing and replacement; no private fallback renderer is added.

## Verification

- The new installed-DSH notification contract check failed against the old artifact because the Git pane had no injected notification callback, then passed after rebuilding. It exercises the real registry's notification implementation with inert non-rendering shell dependencies: repeated success feedback receives fresh ids, and a guard message remains non-success.
- Rebuilt both distribution targets; only the browser artifact and its source map changed. Ran the complete read-only gate through the bundled Node and already installed tools: TypeScript, Biome (99 files), all 384 tests, and in-memory artifact freshness passed. Direct invocation avoided pnpm's attempted automatic switch to the pinned package-manager version; no dependency or package-manager installation was needed.
- The installed DSH 0.2.2-rc.3 contract check passed for five menu target types, 23 commands and shared Toast feedback.
- The existing GUI's public plugin stream advertises revision `40ac085c4722`. Its served executable matches the rebuilt browser artifact exactly after the installed module server's documented combo preparation (strip bundle-local debug trailers, append a separator and replace the sourcemap trailer). The served artifact has the shared Toast binding and no private notice class.
- A separate read-only UI/UX review found no blocking issue; terminology and wrapping suggestions were applied. Browser control was unavailable, so actual Toast appearance, animation, theme contrast and accessibility announcements still require a user click-through after refreshing the existing page. No replacement server was launched, and no HMR behavior is promised.
